# МӨЧ — бодит хэмжилтийн эхний суурь

Энэ өөрчлөлт тусгаарласан эх кодын хуулбарт хийгдсэн. Ажиллаж буй сайт, өгөгдлийн сан, Moch Office-д нийтлээгүй. Төлбөртэй AI, шинэ үйлчилгээ эсвэл хуваарьт ажил нэмээгүй.

## Одоо юу хийдэг вэ

1. Шинээр амжилттай болсон төлбөрийг анх бүртгэгдсэн цагаар нь нэг удаа баримтжуулах нэмэлт өгөгдлийн бүтэц бэлтгэсэн. Дахин шалгах, давтагдсан webhook нь борлуулалтыг дахин тоолохгүй.
2. Зөвхөн серверийн нууц түлхүүрээр нэвтэрдэг `/api/learning-overview` нь хугацааны нэгтгэл буцаана. Хувийн захидал, нэр, зураг, холбоосын нууц код, харилцагчийн жагсаалт буцаахгүй.
3. Нэгтгэлийг шалгаад Монгол хэлээр тайлан гаргана. Бүртгэсэн борлуулалт, төлбөрийн байгууллагын баталгаа, буцаалт, зардлыг тусад нь авч үзнэ. Мэдэхгүй утгыг тэг эсвэл ашиг гэж харуулахгүй.

Энэ шатанд орлогын бүртгэлийн суурь болон унших холболт бэлтгэгдсэн. Хэрэглэгчийн алхмын хэмжилт, хүргэлтийн алдаа, төлбөрийн байгууллагатай тулгах ажиллагаа, Office-ийн дэлгэц, долоо хоногийн автомат ажил хараахан холбогдоогүй. Тайлан үнэ, төлбөр, сайт эсвэл харилцагчийн мэдээллийг өөрчлөхгүй.

## Яагаад хуучин мэдээллээс долоо хоногийн борлуулалт гаргахгүй вэ

Одоогийн `payments` нь `created_at`, `updated_at`-тай боловч анхны амжилттай төлбөрийн цаггүй. Дараа дахин шалгахад `updated_at` өөрчлөгддөг. Энэ цагаар орлогыг ангилбал өмнөх борлуулалт өөр долоо хоногт шилжиж болно.

Шинэ бүртгэл нь идэвхжүүлснээс хойших анхны амжилтын ажиглалтыг авна; банкны бодит шилжүүлгийн цаг гэж нэрлэхгүй. Хуучин төлөгдсөн мөрүүдийн цагийг таамгаар нөхөхгүй. Бүрэн хэмжсэн хугацаа эхлэхээс өмнөх эсвэл хэмжилтийн алдаатай хугацаанд reader тайлан гаргахгүй. Энэ нь борлуулалт тэг байсан гэсэн үг биш.

## Одоогийн бүтээгдэхүүний урсгалын анхаарах зүйл

Болзооны урьдчилан харах алхам заавал биш. Хэрэглэгч урьдчилан харахгүйгээр төлж болно; эрхийн кодоо тусад нь авч дараа нь ашиглаж болно. Иймд `эхэлсэн → урьдчилан харсан → төлбөр → холбоос` гэж бүгдийг заавал дараалсан хүмүүс мэт тооцох нь буруу.

Одоогийн reader `funnel: null` буцаана. Дараагийн шатанд нэг бүтээлд хамаарах таних дугаар, заавал болон сонголттой алхмуудын тусдаа хэмжилт, төлбөр/холбоостой сервер дээр баталсан холбоос хэрэгтэй. Тайлангийн одоогийн strict nested funnel форматыг бодит optional-preview урсгалд шууд бөглөхгүй.

## Локал шалгах

```text
npm ci --ignore-scripts
npm test
npm run review:demo
node tools/moch-learning/run-review.mjs tools/moch-learning/examples/demo-snapshot.json reports/example.md
```

Жишээний тоонууд зохиомол, `demo` гэсэн тэмдэглэгээтэй. Бодит борлуулалт биш. Файлыг дарж бичихгүй.

2026-09-29, Windows / Node 24.19: нийт 338 шалгалтаас 336 тэнцсэн; шинэ хэмжилтийн 68 шалгалт бүгд тэнцсэн. Үлдсэн хоёр нь өөрчлөгдөөгүй `date-plan-http.test.js:164`, `date-plan-service.test.js:55` дахь POSIX `0600` файлын эрхийн шалгалт: Windows `0666` гэж мэдээлсэн. Эдгээр шалгалт болон хамаарах үндсэн код snapshot-оос өөрчлөгдөөгүй. Mac дээр snapshot-ийн өмнөх 270 шалгалт тэнцсэн баримт source handoff-д бий. Windows-ийн private-file ACL-ийн тусдаа баталгаа энэ ажлаар хийгдээгүй; бүрэн багц тэнцсэн гэж үзэхгүй.

## Холбох тохиргоо

Эхлээд тусдаа туршилтын өгөгдлийн санд source migration-уудын шаардлагатай бүтцийг шалгана. Шинэ migration-ийг тэнд туршиж, reader-ийг тухайн тестийн орчинд холбоно. Нийтлэгдээгүй төлбөрийн өөрчлөлтүүд болон production schema-ийн ялгааг [SOURCE_HANDOFF.md](SOURCE_HANDOFF.md)-ээс харна. Энэ branch-ийг бүхэлд нь production руу нийтлэхэд бэлэн гэж үзэхгүй.

Reader серверийн тохиргоо:

- `MOCH_LEARNING_TOKEN`: санамсаргүй үүсгэсэн 32–256 URL-safe тэмдэгтийн нууц түлхүүр; зөвхөн серверт.
- `MOCH_LEARNING_ENVIRONMENT`: `test`, `demo`, эсвэл шалгаж баталсан бодит орчинд `production`.
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`: тусдаа тестийн өгөгдлийн сан. Тохиргоо байхгүй бол reader хаалттай.

Тайлан уншигчийн тохиргоо:

- `MOCH_READER_URL`: reader-ийн бүтэн HTTPS `/api/learning-overview` хаяг. Локал туршилтад loopback HTTP зөвшөөрнө.
- `MOCH_READER_TOKEN`: дээрх reader-ийн нууц түлхүүр. URL, frontend, тайлан эсвэл repository-д оруулахгүй.
- `MOCH_READER_FROM`, `MOCH_READER_TO`: хоёуланг нь ISO цагтай өгвөл `[from,to)` хугацааг уншина. Хамгийн ихдээ 31 хоног.
- Хугацааг өгөөгүй бол Улаанбаатарын цагаар өнгөрсөн бүтэн 7 хоногийг уншина. Шинээр эхэлсэн хэмжилтэд 7 хоног бүрдээгүй байж болох тул энэ үед хэмжиж эхэлснээс хойших богино хугацаа сонгоно.

```text
npm run review:bolzoo -- reports/bolzoo-review.md
```

Нууц түлхүүрийг shell history-д бичихгүйгээр өөрийн серверийн нууц тохиргоо эсвэл орчны хувьсагчаар нийлүүлнэ. Reader-ийн өгсөн шинэ мэдээллийг л одоогийн шийдвэрт авч үзнэ; тайлангийн зөвшөөрсөн шинэ байх хугацаа 5 минут. Файлыг дараа нь нээсэн хугацаанд шинэ хэвээр гэж үзэхгүй.

## Үйл ажиллагааны хязгаар

Reader-ийг түр зогсоохдоо `MOCH_LEARNING_TOKEN`-ийг серверийн тохиргооноос авна; төлбөрийн урсгал тусдаа хэвээр. Өгөгдлийн сангийн capture trigger-ийг унтрааж дахин асаах нь өнгөрсөн хугацааны цоорхойг автоматаар илрүүлэхгүй. Түүнийг салгах шаардлагатай бол эхлээд coverage-ийг дутуу гэж тэмдэглэж, шинэ хэмжилтийн эхлэх үеийг тусад нь тогтоох хэрэгтэй; хуучин хугацааг бүрэн гэж буцааж тэмдэглэхгүй.

Capture хадгалалт алдагдвал төлбөрийг тасалдуулахгүйгээр хэмжилт дутуу гэсэн тэмдэг тавихыг оролдоно. Хэрэв өгөгдлийн сан тэр тэмдгийг ч хадгалж чадахгүй бол дутуу тоог илрүүлэх баталгаа байхгүй. Ийм учраас энэ бүртгэл төлбөрийн байгууллагатай бие даан тулгах ажиллагааг орлохгүй, тайланд баталгаажсан орлого гэж ашиглагдахгүй. Шинэ migration богино хугацаанд payments хүснэгтийн бичилтийг түгждэг тул production-д хэрэгжүүлэхээс өмнө ачаалал ба одоогийн schema-г шалгана.

## Дараагийн идэвхжүүлэх алхам

Туршилтын өгөгдлийн санд шалгасан өөрчлөлтүүдийг production-ийн бодит хувилбар, хэрэгжсэн schema-тай тулгаж тусад нь нийтлэх багц болгоно. Дараа нь хэмжилтийг эхлүүлж, нэгтгэлийг одоо байгаа Moch Office-д холбоно. Эхний бодит тайлангаас нэг асуудал сонгож, нэг өөрчлөлтийг туршиж, үр дүнг хадгалах/буцаах/тодорхойгүй гэж тэмдэглэдэг мөчлөгийг нэмнэ.

Одоогоор банкны тулгалт, цэвэр ашиг, борлуулалтын өсөлт, бүрэн бие даасан агент ажиллаж эхэлсэн гэж дүгнэх үндэс байхгүй.
